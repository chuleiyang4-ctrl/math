COMPATIBILITY SPEC V2 — paste this before any lesson-writing request
(Claude, ChatGPT, Gemini, or any other tool)
=====================================================================

You are writing ONE complete lesson page for an existing static course
website. The finished HTML file must be ready to upload directly to the
repository root without a build step.

Return one complete HTML document only. Do not include explanations,
Markdown fences, or notes outside the HTML.

Use this exact head structure. Replace the title and description, but do
not remove or duplicate the shared files or KaTeX files.

Do not add theme or font controls. Do not create a top navigation bar.
course-common.js automatically adds the shared course top bar, home link,
search, Lab, Notebook, Math AI, Profile controls, and bottom navigation.

An optional "Think Further" section may appear after Key Idea. Keep it
short: two to four high-quality questions that invite reasoning, transfer,
or prediction. Do not add answer keys, repetitive drills, scores, timers,
grading, or a large exercise bank. The Math AI assistant will provide
guided help later.

3. MATHEMATICS AND KATEX

Write formulas as plain LaTeX inside $...$ for inline math or $$...$$
for display math. The shared script auto-renders both forms.

Do not call katex.render() or renderMathInElement() yourself.
Do not use data-tex attributes.
Never use a bare "&" outside
\begin{aligned}...\end{aligned}; it causes a KaTeX parse error.
Every symbol in the main formula must have one .legend-item explaining
its meaning in plain language.

4. PEDAGOGICAL ORDER

Always follow this order:

plain-language intuition
→ one concrete worked numeric example
→ one simple interactive
→ general formula and symbol legend

Never show the general formula before the worked example.

5. LESSON ID — REQUIRED PRE-PUBLISH CHECK

Before producing the final HTML, find the target lesson in the supplied
course-data.json and copy its "id" exactly into data-lesson-id.

Examples:
  course-data.json id "2.2"   → <body data-lesson-id="2.2">
  course-data.json id "5.5.1" → <body data-lesson-id="5.5.1">
  course-data.json id "B1.3"  → <body data-lesson-id="B1.3">

The value is case-sensitive and punctuation-sensitive. Do not infer or
renumber it. If the requested lesson is missing from course-data.json,
stop and report the missing ID instead of inventing one.

The filename must use the same ID in lowercase, replacing dots with
hyphens:

  2.2   → module-2-2.html
  5.5.1 → module-5-5-1.html
  B1.3  → module-b1-3.html

An incorrect data-lesson-id disables automatic navigation. The shared
script now shows a visible warning when the ID is missing or invalid,
but the error must still be corrected before upload.

6. INTERACTIVE ELEMENTS

Keep the interaction simple and low-risk: drag one point, move a slider,
toggle a small option, or read a live number. WebGL, physics engines,
large libraries, heavy particles, and complex 3D effects belong in the
separate Lab hub and must not be added to a lesson page.

Place the visual inside .interactive-card.
Scope lesson-specific CSS under one unique id, such as #vecCanvas.
Never redefine shared classes such as .formula, .concept-card,
.interactive-card, .legend, .lesson-footer, or navigation classes.

Place lesson-specific JavaScript at the end of body, wrap it in an IIFE,
and do not duplicate or reference navigation code from course-common.js.

7. FINAL SELF-CHECK BEFORE OUTPUT

- Complete HTML document, not a fragment
- English only
- data-lesson-id exactly matches course-data.json
- Filename follows module-{id-with-hyphens}.html
- KaTeX CSS, core script, and auto-render script are present once
- course-common.css and course-common.js are present once
- Intuition → worked example → interactive → formula + legend
- No lesson-authored top navigation, theme switcher, or font switcher
- Optional Think Further section contains only 2-4 reasoning questions
- No duplicated shared class definitions
- Interactive CSS uses a unique id
- Interactive script is wrapped in an IIFE
